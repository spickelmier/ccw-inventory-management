No Database
All data lives in-memory. JSON files are loaded once at server startup via mock_data.py and served entirely from RAM. No persistence between restarts.
Filter Architecture
4 global filters (warehouse, category, status, month) are managed client-side in useFilters.js and sent as query params on every API call.
No State Store
No Pinia or Vuex. Shared state is managed via singleton composables — module-level reactive refs that persist across component mounts.

Composables — Shared State

useFilters.js
Singleton reactive filter state — the same refs are shared across all view mounts. Drives every API call.
selectedPeriod — Ref<string> — 'all' | 'YYYY-MM' | 'QN-YYYY'
selectedLocation — Ref<string> — 'all' | 'San Francisco' | 'London' | 'Tokyo'
selectedCategory — Ref<string> — 'all' | category name (lowercase)
selectedStatus — Ref<string> — 'all' | 'delivered' | 'shipped' | 'processing' | 'backordered'
hasActiveFilters — ComputedRef<boolean> — true if any filter !== 'all'
getCurrentFilters() — returns { warehouse, category, status, month } ready for API calls
resetFilters() — sets all filters back to 'all'
useAuth.js
Mock auth state. User object is locale-aware. No real authentication.
currentUser — ComputedRef<User> — name, jobTitle, department, location, tasks[]
getInitials(name) — returns capitalized initials (e.g. "Rick Spickelmier" → "RS")
logout() — stub, shows browser alert
useI18n.js
Internationalization. Two locales: English and Japanese. Currency switches automatically. Preference persisted to localStorage.
t(key, params?) — translate key with optional placeholder substitution
setLocale(locale) — 'en' | 'ja', persists to localStorage
currentLocale — ComputedRef<string>
currentCurrency — ComputedRef<'USD'|'JPY'>
translateProductName / translateWarehouse / translateCustomerName — locale-aware lookups

Server-side Filter Logic (main.py)

apply_filters(items, warehouse, category, status)
Sequential filter — skips any param that is None or "all". Warehouse and status match exactly; category matches case-insensitively. Returns a new list, never mutates source data.
filter_by_month(items, month)
If month starts with Q, expands to a list of months via QUARTER_MAP. Otherwise matches by substring against order_date. Skipped if month is None / "all".
Q1-2025 → ['2025-01','2025-02','2025-03']
Q2-2025 → ['2025-04','2025-05','2025-06']
Q3-2025 → ['2025-07','2025-08','2025-09']
Q4-2025 → ['2025-10','2025-11','2025-12']
